# Simulator layout (stage 13)

Include engine/simulator/layout.hpp for the optional standard-C++20 GridLayout value mechanism. A board has immutable 1..64-cell room dimensions, up to 256 fixed rectangular obstacles and 1..256 required interaction cells. The first required cell is the connectivity root. Constructor validation rejects unreachable fixed layouts. Hosts own cell size, world origin, definitions, access policy, furniture identities, finances, scene projection and saves.

Placement holds a positive stable numeric ID, lower-left anchor, unrotated width/depth and quarter-turn rotation 0..3. footprint swaps dimensions on odd rotations. access rotates the front cell outside the footprint. snap rounds finite world coordinates to integer cells and rejects invalid cell sizes or excessive results. place, move, erase and restore stage a full bounded candidate and publish only after validation; restore sorts by stable ID. Failure preserves the old board. IDs must be unique; up to 256 placements are supported.

Validation rejects invalid dimensions/rotations, room overflow, overlapping solids, furniture less than one cell apart, blocked or out-of-room access/required cells and destinations disconnected from the root. Flood fill checks four-neighbour reachability; it is validation, not an actor navigation follower or crowd avoidance system. blocked exposes fixed/furniture solids. The host supplies conservative footprints for furniture, chairs and actor clearance. This is an axis-aligned grid mechanism, not continuous geometry, arbitrary rotation, a navmesh or multilevel building.

OccupancyPool::setEnabled accepts one 0/1 byte per stable point index. It rejects disabling a claimed point, preserves remaining holders and tokens, and stages waiter promotion to newly enabled free points. All points may be disabled; requests then wait. Compact queues require every point enabled. restore respects the current mask. Hosts persist the mask's source (such as layout) and jointly validate claims; no enabled state is silently added to core snapshots.

CafeGame envelope 7 appends the closed/open flag and two stable table slots. Exact dimensions, footprints, protected interactions, financial totals and enabled seat claims are validated before replacing the session. Formats 1..6 migrate to two default tables and an open cafe. Furniture ledger streams are forbidden in older envelopes. Core wire schema 1 and the browser renderer pin remain unchanged.

The game owns half-metre snapping, table-set prices (6.00 buy, 3.00 sell), close/drain/edit gates, takeaway policy when no tables exist and synchronous prepared-ledger coordination. Editing requires a closed cafe with no guests, active order or tasks. Accepted edits rebuild an engine WaypointGraph of free-cell centres; existing PathFollower/CharacterMotor and guarded arrivals remain responsible for walking. Browser hosts queue edits on the owner thread, show a top-down preview with native validation, and reset transient navigation after successful edits/load. The portable console uses the same policy. Native platform code is unaffected; this standard-library-only header and generic tests are shared by Windows/browser builds.
