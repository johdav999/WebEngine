# Simulator snapshot contract (stage 5)

Runtime::save() returns canonical bounded version-1 bytes; Runtime::restore(span) validates a detached candidate and publishes only on success. Integers are explicit little-endian 64-bit values. Resources and process definitions are compared exactly, avoiding fingerprint collisions. Unknown versions return UnsupportedVersion, changed catalogs DefinitionMismatch, malformed data InvalidSnapshot. Limits::snapshotBytes defaults to 8 MiB. save throws length_error when this limit is exceeded.

Snapshots contain time, stable IDs and next-ID counters, inventories, reservations, stations, workers, jobs, customers, orders and receipts. Validation checks ownership, references, state, recipe batches, deadline constraints and recomputed stock/output claims. Restore uses a fresh epoch; all pre-restore handles are stale. Rebind stable IDs using epoch(), rebuild movement requests, and clear host commands. Events are deliberately omitted and no historical effects are emitted.

receiptSequence() exposes the monotonic receipt high-water mark. The game owns wallet and applied receipt bookkeeping and must persist both with core bytes. Retry pending receipts idempotently, then acknowledge. Core snapshots alone cannot provide wallet consistency. Persistence is single-owner local state, not authentication or distributed payment delivery. Future versions require explicit migration; no migration is currently provided.

CafeGame src/simulation.hpp implements the combined envelope and immediate-arrival adapter, browser localStorage controls, and a portable native console host in tests/session_host.cpp. CafeGame bundles these unreleased module sources independently of its pinned renderer.
