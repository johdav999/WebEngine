# Simulator demand and satisfaction (stage 14)

Include engine/simulator/demand.hpp for optional standard-C++20 DemandRandom, ArrivalTimer, SatisfactionInputs/Weights, satisfaction and patienceScore. They own no Runtime, clock, scene, profiles, prices, arrivals or reviews. Browser and native consumers share the same portable source/tests. Hosts compose these values with existing Runtime::arriveCustomer(patience), service deadlines and delivery receipts.

DemandRandom is a nonzero xorshift32 stream with typed RandomState{value,draws}. uniform(bound) returns [0,bound) using rejection over the actual nonzero generator domain, preserving state on invalid bounds, draw-counter overflow or the 1024-attempt limit. restore rejects zero states. Unsigned operations and integer rejection are identical across hosts. Copy a candidate stream when coordinating a potentially rejected game action; publish it only after acceptance. No default distribution library, wall-clock seed or global stream is used.

ArrivalTimer holds a 0..60000-millisecond remaining duration. elapse rejects negative deltas and clamps at zero; restore validates the bound. It does not emit visits, draw randomness, repeat or own time. The host advances to its boundary, attempts an arrival and schedules the next interval. A held countdown does not accumulate offline catch-up. satisfaction validates each 0..1000 input/weight and computes the integer weighted mean with positive total weight. patienceScore validates nonnegative elapsed time and a positive budget up to one year, then returns a 0..1000 linear score, zero at/after expiry. Neither changes core deadlines or pays money.

CafeGame supplies regular, commuter and espresso-enthusiast definitions, 120/90/150-second shared queue/service patience, preference weights, commuter takeaway, a bounded three-person queue and eight live guests. New browser shifts enable traffic; the diagnostic simulation defaults to manual traffic. Countdown starts at 12 seconds; subsequent intervals are 30000 - reputation*10 + uniform(10001) milliseconds. Reputation is the integer lifetime review average, initially 750. Full floors miss visits and reschedule; closed/disabled traffic freezes the countdown without consuming random values. Profile randomness commits only for admitted automatic guests; manual profile selection consumes none. Simulation advance splits at arrival boundaries. Closing neutrally clears queued guests while current service finishes.

At delivery the game records one weighted review from remaining patience, actual freshness/production quality, machine/table cleanliness and available preferred seating. Commuters take coffee away. Cancellation, expiration and abandonment without coffee record one zero review; closing and migrated terminal guests are neutral. Review ownership remains with stable guest records until retirement, with bounded lifetime aggregates thereafter. Coffee prices and the Ledger receipt protocol remain unchanged.

Cafe envelope 8 appends RNG state/draw count, traffic/countdown, admissions/missed visits, review totals, baseline pre-stage-14 sales, last review inputs and exact per-guest profile/creation-time/patience/outcome. Candidate validation checks core deadlines/states, profile definitions, review arithmetic and paid-service counts before publishing. Formats 1..7 inherit manual traffic, the fixed seed/countdown, original regular patience and no retroactive reviews. Core snapshots stay schema 1, storage slot and renderer pin stay unchanged.
