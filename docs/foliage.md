# Foliage

The opt-in `WebEngine::Foliage` (`engine_foliage`) library in `engine/foliage.hpp`
provides deterministic surface placement, bulk mesh projection, bounded
synchronous cell streaming, GPU wind, independent trunk collision and persistent
plant removals. Browser WebGPU/WebGL2 and Windows D3D12 share instance, material,
shadow and recovery contracts. An explicit CPU reference path remains available.
See [M1–5 validation](foliage-validation.md) and [M6 validation](foliage-dense-validation.md)
for checks actually run; this feature does not establish physical mobile acceptance.

## Definitions and placement

Publish a `FoliageCatalog::create(FoliageDefinition)` once and share it. The
catalog copies and validates definitions before publication. Species have stable
nonzero numeric IDs, static immutable meshes, optional per-detail bend weights,
density, spacing, height/slope/surface filters, scale ranges, tint, ground
alignment, distance/detail/shadow settings and optional trunk dimensions.
Supply opaque trunk geometry and alpha-masked, double-sided leaf/grass cards
through existing `Material` resources. Materials and meshes remain shared; the
library does not generate art or force all materials into a cutout mode.

`generateFoliageCell` samples a globally anchored jittered lattice per species.
Stable IDs contain species plus signed global lattice X/Z coordinates. Seeded
hashing supplies jitter, acceptance, yaw, uniform scale and wind phase without a
mutable random generator. Negative cells, generation order and residency do not
change IDs or placements. At most one candidate occupies each lattice site.
Spacing within one species holds across cell boundaries; species do not mutually
exclude one another. Floating-point positions have normal float precision.

Density is a target maximum per square metre. The lattice step is the larger of
`sqrt(1/density)` and `minimumSpacing/0.6`; jitter occupies the central 40% of
each lattice square. Spacing can therefore cap realized density. Rejected
surface/mask/exclusion candidates are not replaced. This is deliberately bounded
and repeatable, rather than a maximal packing or Poisson-disc sampler.

The synchronous `FoliageSampler` takes source/world X/Z and returns optional
height, +Y-oriented normal and surface-mask bits. Null means a hole or unavailable
source; malformed samples fail the entire candidate publication. The terrain
adapter owns an immutable `TerrainAsset` and supports translation. It uses full
source triangles, including holes, independently of chunk residency/render LOD.
Rotated/scaled terrain, mesh surfaces and biome masks can use an application
sampler. Games own biome composition, exclusions and terrain-edit notifications.

Definitions allow at most 64 species, eight explicit distance details per species,
1,024 rectangular exclusions, 65,536 candidate visits and 16,384 accepted instances
per cell. Defaults are 8,192 candidates and 4,096 instances. Definition validation
preflights the worst-case candidate count; an accepted-instance overflow rejects
generation. World focus is bounded to +/-100,000 metres; cell size is 1..1,024.
Source geometry is static, bounded to 65,536 vertices per detail, without skinning
or morph targets. Bend weights must cover every vertex and lie in [0,1].

## Ownership, streaming and publication

```cpp
auto catalog = engine::FoliageCatalog::create(definition);
engine::FoliageStreamSettings settings;
settings.collision = true;
engine::FoliageStream foliage(scene, catalog,
    engine::foliageTerrainSampler(terrain, terrainOrigin), settings);

// At an idle boundary, before scene simulation/physics reconciliation:
foliage.update(visualFocusXZ, gameplayFocusXZ);
// After simulation, using the application's accumulated simulation seconds:
foliage.present(visualFocusXZ, simulationSeconds, wind);
// Before releasing the owner while retaining this scene:
foliage.clear();
```

The stream borrows its Scene; the scene must outlive all method calls. The stream
retains catalog and sampler captures. The scene owns generated root actors and
ordinary components. Cross-frame references use generation-checked handles.
Generated subtrees are archive-transient; save definitions/content references and
removals in the application's save envelope, then recreate the projection.
The destructor does not access a potentially destroyed scene or remove its actors.
Call `clear()` explicitly when the scene continues to live after discarding a stream.
Do not manually modify/reparent/destroy its generated projection. Pending subtree
removal rejects mutations until flushed. An externally deleted complete cell is
recognized as absent and can be regenerated by the next update.

Scene transforms must be identity, with world-space placements. Update, present,
replaceSource, removal publication and clear require an idle hierarchy. No second
scene graph, renderer registry, frame phase or simulation scheduler is introduced.
Call update from the host's existing pre-simulation preparation boundary; the
normal Scene reconciliation owns creation/removal of physics bodies.

Visual and collision radii have separate focus positions and hard resident limits.
Each square requested radius must fit its resident limit. Existing cells within
the outer hysteresis band can remain if budget permits; nearer cells win.
`buildsPerUpdate` bounds total new visual/collision cell preparation, prioritizing
collision. Stats expose pending admissions. Gameplay must wait for required
collision coverage before moving into an unprepared area; the stream is not a
movement gate. Radius is 0..8, hysteresis 0..4 cells, residents <=512 per kind and
admissions <=64 per update. Default visual radius is one, collision disabled,
collision radius zero and four admissions/update. Product count limits still
matter: choose modest per-cell and resident budgets for the target device.

Every update stages all admitted cells before changing the published set. Source
exceptions, validation and preparation failures preserve existing cells, handles,
removals and counters. Adoption failures roll back attached candidates before old
cells retire. `replaceSource` synchronously stages replacements for all resident
cells before swapping source/projection; absent cells use the accepted new source.
`setRemoved` uses the same complete replacement boundary. These explicit whole-set
operations are not constrained by the incremental admission budget.

This version has no workers, retained completion callbacks or asynchronous cell
publication: there are no late results to apply after eviction/source replacement.
Applications must not run a stream concurrently or mutate its scene inside a
sampler. Sampler captures must describe stable source data during each operation.
External asynchronous source work should finish and validate before an idle
`replaceSource`; any future worker adapter must add request identity/cancellation.

## Rendering, wind and detail

`FoliageStreamSettings::rendering` defaults to `FoliageRendering::GpuInstances`.
Each visual cell owns one generic `MeshInstancesComponent` per species/detail,
instead of a scene component per plant. Immutable `MeshInstanceSet` resources
contain 64-byte TRS/tint/key/phase/visibility records and cached matrices. Instances
share source meshes, materials and authored bend data. Compatible draws batch
on WebGPU, WebGL2 and direct D3D12, including shadow passes. Applications choose
presentation budgets for actual capabilities; changing lattice rules requires a
content identity change. The example uses equal GPU residency on both browsers.

Explicit detail distances switch source meshes with configurable hysteresis.
Each detail can use different topology and matching bend weights. Existing static
mesh LOD chains and independent shadow LOD continue to work for rigid draws.
Weighted wind draws use the selected explicit source detail because its immutable
bend sidecar belongs to that exact topology. Distance controls can reduce
or omit shadows and hide far geometry. Collision and persistent IDs do not follow
these presentation choices. Multi-camera collection shares the application's
chosen foliage detail/focus; no per-camera foliage detail ownership is added.

GPU wind uses authored weight squared, stable phase, world X/Z direction,
amplitude, frequency and gust. One shared `MeshWindState` supplies reduced wave
angles, direction and amplitude in 32 bytes. `MeshBend` stores immutable weights
and surface gradients alongside the source mesh. Vertex shaders apply the same
displacement in color and shadow passes; zero weights pin roots. They correct
normals/tangents using the deformation Jacobian, with a bounded denominator near
folds. Culling and picking use conservative maximum-amplitude bounds, independent
of time; triangle picking evaluates the same displaced vertex positions.

`present` receives time rather than owning a clock. Supplying unchanged focus,
time and wind retains existing resources and avoids revision churn while paused.
Wind-only updates keep immutable placements, matrices and instance uploads intact.
GPU upload caching remains backend-owned. Scene
collection and camera visibility never advance wind; all resident weighted plants
receive the supplied time even if hidden. The application freezes time during
pause/suspension and can deliberately seek/reset it. Candidate stream preparation
finishes before publishing any plant's presentation state.

Choose `FoliageRendering::CpuMeshes` explicitly for the legacy reference path.
It uses per-plant `FoliageMeshComponent`/`MorphPose`, rebuilt triangle normals and
reorthogonalized tangents, exact deformed bounds and dynamic vertex uploads.
GPU normals may differ from these triangle-rebuilt normals. CPU work scales with
weighted vertices and prevents batching independently deformed plants.

Bulk components are generic engine-core runtime projections for opaque/masked
static meshes. They reject skinning, source morph targets, water and blended
materials, and do not receive projected decals. Their source records are compact;
the renderer still expands CPU draw descriptors and uses existing 256-byte GPU
object slots (176 bytes of attributes). WebGL packs those attributes to a 176-byte
stride to stay below its 255-byte limit. This is CPU culling plus direct instanced
drawing, without GPU culling, indirect draws, impostor baking, interactive bending,
leaf translucency or a universal foliage throughput guarantee.

## Collision, harvesting and saves

Opt-in trunk capsules (or spheres when height equals diameter) use existing
immutable shapes in one static compound body per collision cell. Shape dimensions
incorporate plant scale; actors remain world-root, unit scale. Ground alignment
also applies to trunks. Grass has no collision by default. Visual distance,
shadow settings, LOD and wind never change these shapes or collision focus.

Map a picked `SelectionHit` with `placement(hit.surface, hit.instanceKey)`, then
use `remove(id)`. A bulk component handle alone is ambiguous and returns no ID;
CPU projection keeps `placement(ComponentId)` compatibility. Local keys are
ephemeral and scoped by the generation-checked component handle; save full FoliageIds.
Game policy decides whether it is harvestable, rewards, regrowth and network
authority. `setRemoved` validates bounds, species and duplicate IDs before
publishing; accepted IDs may refer to currently absent plants. Overrides remain
through clear, unloading and source height changes. The default limit is 65,536
removals, configurable up to 262,144.

`saveRemoved` / `loadRemoved` use bounded `WEFO 1` text with world ID, seed and
sorted full placement IDs. Unknown versions/content/species, duplicates,
truncation, count/byte overflow and trailing data reject without replacing valid
state. Storage and content migration remain application responsibilities. Bump
the definition's game-owned world identity when species IDs, lattice parameters
or placement policy change; seed/world matching is compatibility, not a content
hash or authentication. Only removed/not-removed overrides are supplied here;
additional growth/health/destruction state belongs in a game-owned save.

## Build and exercise

Use the repository-local SDK pinned by `.emscripten-version`, and the prerequisites
in [README](../README.md). Enable all three flags to build the contracts and demo:

```powershell
./.tools/emsdk/upstream/emscripten/emcmake.exe cmake -S . -B build/web-release -G Ninja -DCMAKE_BUILD_TYPE=Release -DWEBENGINE_BUILD_FOLIAGE=ON -DWEBENGINE_BUILD_FOLIAGE_TESTS=ON -DWEBENGINE_BUILD_FOLIAGE_DEMO=ON
cmake --build build/web-release --target foliage_tests foliage_demo -j 4
ctest --test-dir build/web-release -R '^foliage_contracts$' --output-on-failure
# Serve build/web-release/foliage-site; set FOLIAGE_URL, NODE_PATH and
# BROWSER_EXECUTABLE for your installed Playwright/browser, then:
node scripts/foliage-browser-smoke.cjs
node scripts/foliage-dense-smoke.cjs

cmake -S . -B build/foliage-windows -G "Visual Studio 17 2022" -A x64 -DWEBENGINE_BUILD_WINDOWS=ON -DWEBENGINE_WINDOWS_DAWN=OFF -DWEBENGINE_WINDOWS_D3D12=ON -DWEBENGINE_BUILD_FOLIAGE=ON -DWEBENGINE_BUILD_FOLIAGE_TESTS=ON -DWEBENGINE_BUILD_FOLIAGE_DEMO=ON
cmake --build build/foliage-windows --config Release --target foliage_tests foliage_demo_windows --parallel 6
ctest --test-dir build/foliage-windows -C Release -R '^foliage_contracts$' --output-on-failure
./build/foliage-windows/Release/foliage_demo_windows.exe --d3d12 --smoke build/foliage-native
./build/foliage-windows/Release/foliage_demo_windows.exe --d3d12 --benchmark --smoke build/foliage-dense-native-gpu
./build/foliage-windows/Release/foliage_demo_windows.exe --d3d12 --benchmark --cpu --smoke build/foliage-dense-native-cpu
```

The browser and Windows example share `examples/foliage/scene.hpp`. Controls toggle
wind, harvest the nearest plant, move visual focus while preserving collision,
regrow plants, save/load overrides through host storage and pause/resume. Example
biome/art/harvest rules are outside the reusable library.
Browser `?benchmark=1` selects a fixed-seed 10,000-clump fixture; add `&cpu=1`
for its CPU reference. Both use identical eight-vertex masked unlit clumps and
time 0.75 for image comparison; unlit shading isolates positional parity from
the two normal reconstruction methods. The dense fixture disables shadows;
the normal clearing separately exercises wind in color/shadow passes.
